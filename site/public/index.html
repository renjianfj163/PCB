我们重新设计了和 AI 协作的方式：不熟悉代码的人可以用自然语言把工作做完；熟悉代码的人可以打开本机的 VS Code 或 Cursor，和 OMP、OMP-ckpt 一起开发。

HOW YOU WORK

不只是 AI 对话，而是一个真正的工作入口

PCB 基于 Oh My Pi（OMP）构建。我们没有重新实现一套 AI Agent，也没有在 OMP 之外再加一层对话引擎。每个会话都由本机运行的 OMP RPC 子进程处理。

我们重点改进的，是你和 OMP 之间的交互，以及 AI 辅助开发时的工作流程。

01

更友好的自然语言交互

让不会编程的人，也能用 AI 完成实际工作。

我们为 OMP 做了更直观的图形界面，把原本偏向开发者的交互，收成普通用户也能跟着走的步骤。

  • Chat

    用自然语言交流、提出需求、讨论问题。这一步不改文件。

  • Plan

    让 AI 阅读项目、分析需求，并生成可以检查的实施计划。

  • Build

    你批准计划之后，交由 OMP 修改文件并完成相关任务。

  • Review

    查看实际修改，按需要接受，或恢复到之前的状态。

不需要先弄懂底层命令。沿着对话和计划，就可以把工作往前做。

02

VS Code / Cursor + OMP + OMP-ckpt

给开发者一个更完整的 AI 编程协作环境。

对熟悉代码的人，PCB 不只是一个对话窗口，也可以是进入项目的统一入口。可以直接打开本机已经安装的桌面版 VS Code 或 Cursor，在熟悉的 IDE 里继续开发，并结合 OMP 与 OMP-ckpt 做 AI 辅助编程。

OMP-ckpt：让 AI 改代码的过程更容易检查，也更容易恢复。

它解决的是连续修改之后，不容易看清改了哪里、也不容易退回去的问题。

  • 修改记录

    为开发过程建立检查点，保留修改前后的状态。

  • 差异检查

    查看文件发生了哪些变化。

  • 选择性恢复

    发现问题时，用检查点恢复之前的文件状态。

  • 开发过程保护

    AI 可以参与更复杂的修改，人仍然留有检查和恢复的空间。

普通用户可以直接使用 PCB。开发者可以再进入 IDE，用自己熟悉的方式继续检查、修改和开发。

03

从开发工具走向产品创建

让 AI 不仅帮你写代码，也帮你把想法做成产品。

我们希望 PCB 逐步形成一套更完整的产品创建流程：借助 AI 开发软件，再调用专门的 Skill，协助完成产品演示、内容制作、推广和商业化。这些是方向，下面的路线图会逐项标明，现在还没有提供。

LOCAL FIRST

本地运行，用户掌握主动权

PCB 负责友好的交互、工作流程和必要的安全控制。OMP 负责真正的 AI 工作。

本地 AI 引擎

OMP 作为本机子进程运行，负责对话、计划和文件操作。

本地服务

PCB 服务只监听 127.0.0.1，不把这个工作环境放到公网。

操作授权

执行计划需要你明确批准。危险命令需要额外确认。

文件保护

通过检查点和变更审查，降低 AI 修改项目带来的风险。

开放的开发环境

可以使用本机已经安装的 VS Code 或 Cursor。PCB 不附带、也不下载编辑器。

FAQ

常见问题

关于它是什么、OMP，以及现在还没有的能力。

PCB 是什么？

PCB 是基于 Oh My Pi 深度扩展的本地 AI 工作平台。

PCB 和 Oh My Pi 是什么关系？

Oh My Pi（OMP）是本机上的 AI 引擎。

OMP-ckpt 做什么？

它为 AI 修改文件留下检查点。

一定要安装 VS Code 或 Cursor 吗？

不一定。

AI 会自动修改我的文件吗？

普通对话不会改文件。

修改出错怎么办？

可以按修改块检查、接受或恢复。

项目文件会上传到 PCB 的网站吗？

不会。

演示、发布和支付现在能用吗？

不能。这三项都在规划中。
