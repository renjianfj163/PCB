## 一、为什么内嵌永远打不开，以及现在的解法

### 实测数据（本机，2026-11-17）

| 地址 | `curl` 6 秒结果 | DNS 解析 | 能否内嵌 |
| --- | --- | --- | --- |
| `www.google.com` | 超时，无回应 | `69.171.235.22`、`2001::1`（都不是 Google 的 IP） | 否 |
| `cn.bing.com` | 200 | `202.89.233.101`、`202.89.233.100` | 否，`X-Frame-Options: SAMEORIGIN` |
| `example.com` | 200 | 正常 | 是 |
| `127.0.0.1:7777` | — | 本机 | 否（按设计拒绝） |

两条独立的限制，之前混在一起，现在分开：

1. **框架层**：站点自己声明不许别人框它（`X-Frame-Options: DENY/SAMEORIGIN`、CSP `frame-ancestors`）。任何 iframe 都做不到。
2. **网络层**：这台机器的系统 DNS 把 `www.google.com` 解析到别人家的 IP，TCP 无回应。`curl`、系统浏览器、iframe 走同一条路，全都打不开。

### 解法：本机浏览器截图

iframe 不行，但「本地浏览器自己加载、自己截图」不涉及谁框谁，也不走系统 DNS（Chrome 会尝试加密 DNS），两条限制同时绕过。

- 端点：`GET /api/frame/shot?url=…` → `{ ok, image(data:image/png;base64), url, reason?, ms }`
- 实现：`server/screenshot.ts`，找本机 Chrome / Edge（`PCB_CHROME` 可覆盖），一次性 profile，参数
  `--headless=new --disable-gpu --hide-scrollbars --virtual-time-budget=9000 --window-size=820,1500 --screenshot=…`
- 防护与 `frame/check` 一致：拒绝本机地址、内网、CGNAT、link-local；30 秒上限；结束后删临时目录

| 页面 | 结果 | 耗时 | PNG |
| --- | --- | --- | --- |
| `www.google.com` | 成功，整页 | 14.1 s | 33.7 KB / 820×1500 |
| `cn.bing.com` | 成功 | 1.7 s | 19.1 KB |

界面：打不开的卡片第一按钮是「截图看看」，并显示 `域名解析到 <ip>`；截图下方写明「能看不能点」，给「重新截一张」「用系统浏览器打开」，点图放大（Esc 关闭）。

边界：静止图片，点不了、翻不了页；每次起一个浏览器进程，慢站最多等 30 秒；系统浏览器里 `www.google.com` 仍然打不开。

## 二、终端：真终端形态

### 三个阶段

1. 最早每条命令一张卡：边框 + 圆角 + `你运行的` 标签 + 折叠按钮 —— 不像终端。
2. 改成通屏滚动，但底部仍有一条独立输入框 —— 还是「有个输入框」。
3. **现在**：输入行就是滚动区的最后一行，提示符、命令、输出在同一个等宽列里，没有任何边框。

```
PS D:\Developer\3GPP_search> Get-ChildItem -Name | Select-Object -First 4
.omp
.pytest_cache
.ruff_cache
.venv
PS D:\Developer\3GPP_search> cd ..
PS D:\Developer> Get-Location

Path
----
D:\Developer

PS D:\Developer> ▏            ← 光标就在这里，不是另一个框
```

### 交互

| 行为 | 实现 |
| --- | --- |
| 敲完回车 | 命令行留在卷里（带它当时的提示符），输出紧跟其下，再出现新提示符 |
| 提示符 | `PS <绝对路径>>`（PowerShell）/ `<绝对路径>>`（cmd），和 shell 自己打印的一致 |
| 键盘归属 | 终端页打开即聚焦；**焦点不在任何输入控件上时，打字直接落到提示符**（自动补字符）；Enter 直接执行。实测：先把焦点丢到 body，再敲 `dir /b` → 字符进了提示符，回车就跑了 |
| 跑完 | 命令结束后自动把焦点还给提示符（输入框用 `readOnly` 而不是 `disabled`，否则会失焦） |
| ↑ / ↓ | 翻历史命令 |
| 静默命令 | 成功且无输出就什么都不打印（`cd ..` 不再出现「（没有输出）」）；失败才显示退出码 |
| shell 选择 | 顶部子标题右侧的紧凑下拉（`cmd.exe` / `PowerShell`），不占输入行；存 `localStorage["pcb.shell"]` |
| 占位提示 | 只在这个面板没拿到焦点时显示「在此输入命令」，聚焦后消失 |
| 长输出 | 单条超过 4000 字符截断；整条命令输出超过 64 KB 服务端截断并标注 |

限制：中文输入法组字不会走「打字直落」，得先点一下输入行（键盘事件在组字期间被跳过）。

### `cd` 现在真的生效

一条命令一个进程，原本 `cd` 无从生效。做法：

- 只对**目录类命令**（`cd`/`chdir`/`pushd`/`popd`/`Set-Location`/`sl`）多跑一步：末尾再要一次当前目录（cmd 用 `& cd`，PowerShell 用 `(Get-Location).Path`）；
- 输出最后一行若是路径形状，就当作新的工作目录，并从输出里剥掉；
- 其它命令完全不动，**退出码保持真实**（不会因为尾巴上的 `cd` 被冲成 0）。

实测：cmd `cd ..` → `cwd: D:\Developer\PCB`；PowerShell `cd src` → `cwd: …\web\src`；`nosuchcmd-xyz` → 退出码 1；`Get-Item nope.zzz` → 退出码 1，报错只引用用户那一行（`+ Get-Item nope.zzz`）。

### 修掉的两个编码 bug

1. PowerShell 用 stdin 送脚本时，stdin 按控制台代码页（GBK）解码，命令里的中文被弄坏（`你好` → `浣犲ソ`）。改成脚本作为**参数**传入（Node 走 UTF-16），中文正常。
2. 早前把 UTF-8 前导和命令拼成一行，报错会回显我们的前导代码。现在前导独占一行，报错只引用用户那一行。

### 安全边界的调整（需要知道）

`POST /api/exec` 原来要求 `cwd` 必须等于某个已存项目目录，这会让 `cd ..` 直接被拒。为了让 `cd` 能工作，改成**只要求目录真实存在**；边界保留在：仅 loopback、必须带 `x-pcb-request` 标记、命令长度 ≤ 2000 字符。这一栏现在可以在任意目录里跑你亲手敲的命令。

## 三、为什么会话会「已结束」，以及现在的自动恢复

一个对话背后是一个 omp 子进程。它会随 PCB 服务退出、机器重启而结束；PCB 存的是对话记录（`.jsonl`），不是常驻的几十个 agent 进程。

- **自动恢复**：打开（或刷新后仍停留的）对话发现进程不在，自己恢复。实测：服务重启、页面不刷新，20 秒内对话自动回来，输入框可用。
- **失败横幅**：万一恢复失败，输入框上方出现「这个对话的后台进程已经退出，恢复后才能继续。」+ `恢复会话` 按钮。实测（人为让 `/resume` 失败）：横幅出现、按钮可点；点一下后横幅消失、输入框解锁、61 条历史消息回放。
- 顶栏右上角的恢复图标仍在（`!alive` 时才显示）。
